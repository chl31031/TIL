# ⚛️ Next.js 실습: 알림 센터(Notification Center) 구현

이 실습에서는 외부 API를 통해 알림 목록을 불러오고, 특정 알림의 읽음 상태를 업데이트하는 기능을 구현합니다.

---

### 1. 주요 구현 기능

- **데이터 페칭(GET)**: `useEffect`를 사용하여 컴포넌트 마운트 시 알림 목록을 로드합니다.
- **상태 업데이트(PATCH)**: 알림의 '읽음/안 읽음' 상태를 서버에 반영하고 화면에 즉시 업데이트합니다.
- **UI 상태 관리**: 로딩 중, 에러 발생 시, 데이터가 없을 때의 각각 다른 UI를 처리합니다.

---

### 2. API 모듈 분리 (`NotificationApi.js`)

관심사 분리를 위해 비동기 통신 로직을 별도의 객체로 정의합니다.

```javascript
const API = "http://localhost:4000/notification";

// 알림 목록 가져오기 (GET)
export const notificationApi = {
  getPost: async () => {
    const res = await fetch(API, {
      method: "GET",
      headers: { "Content-Type": "application/json" },
    });
    return res.json();
  },
};

// 읽음 상태 변경하기 (PATCH)
export const notificationReadApi = {
  setPost: async (id, read) => {
    const readAPI = `${API}/${id}`;
    const res = await fetch(readAPI, {
      method: "PATCH",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ read: read }),
    });
    return res.json();
  },
};
```

### 3. 알림 페이지 컴포넌트 (`page.jsx`)

`"use client"`를 사용하여 클라이언트 사이드에서 동작하는 인터랙티브한 페이지를 구성합니다.

```javascript
"use client";

import { useEffect, useState } from "react";
import { notificationApi, notificationReadApi } from "../api/NotificationApi";
import Header from "../components/Header";

// 스타일 정의 (생략 가능 - 인라인/CSS module 방식 선택)
const loadingStyle = {
  /* ... */
};
const errorStyle = {
  /* ... */
};

export default function NotificationPage() {
  const [notifications, setNotifications] = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [isError, setIsError] = useState(false);

  // 데이터 로드 함수
  const loadData = async () => {
    try {
      const data = await notificationApi.getPost();
      // 데이터 형식 방어 코드
      setNotifications(Array.isArray(data) ? data : data.notification || []);
      // 인위적인 지연 (로딩 UI 확인용)
      await new Promise((resolve) => setTimeout(resolve, 1000));
    } catch (error) {
      setIsError(true);
    } finally {
      setIsLoading(false);
    }
  };

  // 읽음 처리 함수 (Optimistic Update 패턴과 유사)
  const readData = async (id, read) => {
    try {
      await notificationReadApi.setPost(id, !read);
      // 서버 응답 후 로컬 상태 업데이트
      setNotifications((noti) =>
        noti.map((item) => (item.id === id ? { ...item, read: !read } : item)),
      );
    } catch (error) {
      alert("상태 변경에 실패하였습니다.");
    }
  };

  useEffect(() => {
    loadData();
  }, []);

  // 조건부 렌더링
  if (isLoading)
    return <div style={loadingStyle}>데이터를 불러오는 중입니다...</div>;
  if (isError)
    return <div style={errorStyle}>데이터를 가져오는데 실패했습니다.</div>;

  return (
    <div
      style={{ backgroundColor: "#09090b", color: "#fafafa", padding: "20px" }}
    >
      <Header title="구독 관리" showNotification="{false}" />
      <h1 style={{ backgroundColor: "#7c3aed", padding: "20px" }}>알림 센터</h1>

      {notifications.length === 0 ? (
        <p>새로운 알림이 없습니다.</p>
      ) : (
        notifications.map((item) => (
          <div key={item.id} style={loadingStyle}>
            <p>{item.text}</p>
            <div style={{ marginTop: "20px" }}>
              <span>{new Date().toLocaleDateString()}</span>
              <button onClick={() => readData(item.id, item.read)}>
                {item.read ? "읽음" : "안 읽음"}
              </button>
            </div>
          </div>
        ))
      )}
    </div>
  );
}
```

---

### 4. 핵심 이론 정리

1.  **PATCH Method**: 자원의 전체가 아닌 **일부(여기서는 read 속성)**만 수정할 때 사용합니다.
2.  **Promise.all vs 개별 호출**: 여러 데이터가 필요할 땐 효율적이지만, 여기서는 단순 지연을 위해 `setTimeout`과 조합된 Promise를 사용했습니다.
3.  **데이터 방어**: API 응답이 배열이 아닐 경우를 대비해 `Array.isArray()`로 체크하여 런타임 에러를 방지합니다.
