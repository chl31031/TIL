# ⚛️ Next.js 박스오피스 실습 & Zustand 상태 관리

## 1. 서버 컴포넌트 vs 클라이언트 컴포넌트

Next.js App Router의 모든 컴포넌트는 기본적으로 **서버 컴포넌트**입니다. 브라우저 전용 기능이 필요할 때만 클라이언트 컴포넌트로 전환합니다.

| 구분               | 서버 컴포넌트                | 클라이언트 컴포넌트                    |
| :----------------- | :--------------------------- | :------------------------------------- |
| **선언**           | 기본값 (지정 필요 없음)      | 파일 최상단 `"use client"` 명시        |
| **렌더링 위치**    | 서버                         | 브라우저                               |
| **사용 가능 기능** | `async/await` 직접 사용 가능 | `useState`, `useEffect`, 이벤트 핸들러 |

---

## 2. API 통신 및 유틸리티 패턴

효율적인 데이터 페칭을 위해 환경변수와 공통 함수를 분리하여 관리합니다.

### ① 환경변수 (.env)

- `NEXT_PUBLIC_` 접두사를 붙여야 클라이언트 측(브라우저)에서 접근이 가능합니다.
- 예: `process.env.NEXT_PUBLIC_MOVIE_API_KEY`

### ② 유틸리티 함수

- **apiUtils**: 반복되는 `fetch` 로직과 에러 핸들링을 공통화합니다.
- **urlUtils**: 객체 형태의 파라미터를 쿼리 스트링으로 변환해 주는 `urlParamFactory`를 활용합니다.
- **dateUtils**: API 조회에 필요한 날짜 형식(YYYYMMDD)을 생성합니다.

## 3. 박스오피스 실습 프로젝트 구조

KOBIS API를 연동하여 영화 목록과 상세 정보를 보여주는 구조입니다.

- **API 레이어 (`apis/`)**: 통신 로직을 컴포넌트와 분리하여 유지보수성을 높입니다.
- **동적 라우팅**: `[movieCode]` 폴더 구조를 통해 상세 페이지 URL을 생성하고 `useParams()`로 파라미터를 읽어옵니다.

## 4. Zustand 전역 상태 관리

Zustand는 Flux 패턴을 기반으로 한 작고 빠르며 확장 가능한 상태 관리 라이브러리입니다.

### ① Prop Drilling 문제 해결

상위 컴포넌트의 상태를 하위로 전달하기 위해 중간 컴포넌트들이 props를 단순 전달만 하는 현상을 방지합니다.

### ② 스토어 생성 및 사용

```javascript
// src/store/useStore.js
import { create } from "zustand";

export const useStore = create((set) => ({
  count: 0,
  increase: () => set((state) => ({ count: state.count + 1 })),
  setText: (value) => set({ text: value }),
}));

// 컴포넌트에서 사용
const { count, increase } = useStore();
```

## 5. Zustand 심화 및 비동기 처리

### ① 불변성(Immutability) 유지

배열이나 객체 상태를 업데이트할 때는 반드시 **새로운 참조값**을 생성해야 합니다.

- **잘못된 예**: `state.items.push(item)` (원본 수정)
- **올바른 예**: `items: [...state.items, item]` (새 배열 생성)

### ② 비동기 액션 (Async Actions)

별도의 미들웨어 없이 `async/await`를 액션 함수 내에서 직접 사용할 수 있습니다.

```javascript
export const useUserStore = create((set) => ({
  user: null,
  loading: false,
  fetchUser: async () => {
    set({ loading: true });
    try {
      const res = await fetch("...");
      const data = await res.json();
      set({ user: data });
    } finally {
      set({ loading: false });
    }
  },
}));
```

### ③ 관심사 분리 (다중 스토어)

모든 상태를 하나의 스토어에 넣지 않고 `useCartStore`, `useUserStore`, `useUIStore` 등으로 분리하여 관리하는 것이 성능과 가독성 면에서 유리합니다.

## 💡 핵심 요약

1.  **Next.js**: 기본은 서버 컴포넌트, 인터랙션이 필요할 때만 `"use client"`를 사용한다.
2.  **API**: 유틸 함수와 API 레이어를 분리하여 관심사를 격리한다.
3.  **Zustand**: `set()`을 통해 상태를 변경하며, 불변성을 지켜 리렌더링을 보장한다.
4.  **비동기**: 스토어 내에서 `async` 액션을 정의하여 로딩 상태와 데이터를 함께 관리한다.
