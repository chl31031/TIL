# React 리스트 렌더링 및 상태 관리 (이론과 예시)

### 1. 리스트 렌더링 (Rendering List)
React에서 데이터 배열을 UI 요소로 변환할 때는 자바스크립트의 `map()` 메서드를 활용하여 선언적으로 화면을 구성합니다.

* **이론적 배경**: React는 데이터 중심의 라이브러리이므로, 원본 데이터를 기반으로 동일한 구조의 JSX 엘리먼트를 반복 생성하는 방식을 사용합니다.
* **Key 프로퍼티의 역할**: 
    * 리스트 내 각 항목을 식별하는 고유한 ID 역할을 합니다.
    * **성능 최적화**: 어떤 항목이 변경되었는지 React가 즉시 파악하여 해당 부분만 업데이트하므로 전체를 다시 그릴 필요가 없습니다.
    * **주의사항**: 고유한 ID가 없을 때 인덱스(`index`)를 사용하기도 하지만, 배열의 순서가 바뀌거나 중간에 요소가 삽입/삭제될 경우 React가 이전 요소와 새 요소를 혼동할 수 있어 권장하지 않습니다.

**💡 예시 코드:**
```javascript
const fruits = ['사과', '바나나', '딸기'];

function FruitList() {
  return (
    <ul>
      {fruits.map((fruit, index) => (
        // 고유 ID가 없을 경우 최후의 수단으로 index를 사용
        <li key={index}>{fruit}</li>
      ))}
    </ul>
  );
}
```

### 2. 리스트 요소 추가 (Add Item)
상태(State) 배열에 새로운 데이터를 추가할 때는 반드시 **불변성(Immutability)**을 준수해야 합니다.

* **이론적 배경**: React는 이전 상태와 다음 상태의 **메모리 주소(참조값)**가 달라져야 변경을 감지하고 리렌더링을 수행합니다. `push()`나 `splice()`는 원본 배열을 직접 수정하므로 주소값이 변하지 않아 화면이 갱신되지 않을 수 있습니다.
* **방법**: 전개 연산자(`...`)를 사용하여 기존 배열의 요소를 복사하고 새 요소를 포함한 **완전히 새로운 배열**을 생성합니다.

**💡 예시 코드:**
```javascript
const [items, setItems] = useState(['A', 'B']);

const handleAdd = () => {
  const newItem = 'C';
  // 1. 기존 배열 복사 2. 새 항목 추가 -> 새로운 참조값을 가진 배열 생성
  setItems([...items, newItem]); 
};
```

### 3. 리스트 요소 삭제 (Remove Item)
특정 요소를 삭제할 때도 원본을 건드리지 않고, 삭제 대상을 제외한 새로운 배열을 생성합니다.

* **이론적 배경**: 자바스크립트의 `filter()` 메서드는 주어진 조건을 통과하는 요소들만 모아 **새로운 배열을 반환**하므로 리액트의 상태 관리 원칙에 가장 적합합니다.
* **방법**: 각 항목의 고유 ID를 비교하여, 삭제하려는 대상의 ID와 일치하지 않는 데이터들만 추출합니다.

**💡 예시 코드:**
```javascript
const [todos, setTodos] = useState([
  { id: 1, text: '리액트 공부' },
  { id: 2, text: '운동하기' }
]);

const handleRemove = (id) => {
  // id가 일치하지 않는 요소들만 남겨서 새로운 배열로 교체
  setTodos(todos.filter(todo => todo.id !== id));
};
```

### 4. To-Do List 동작 원리 요약
이론적으로 To-Do List는 아래 세 가지 핵심 로직의 조합입니다.

1.  **렌더링**: `map()`을 사용해 상태 배열을 JSX 리스트로 변환.
2.  **생성(추가)**: 사용자의 입력을 받고 `Date.now()` 등으로 고유 ID를 부여하여 `spread` 연산자로 배열 병합.
3.  **제거(삭제)**: 아이템 고유 ID를 `filter` 조건식으로 넘겨 해당 항목을 배열에서 제외.
